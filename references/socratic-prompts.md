# 苏格拉底式提问模板（按学科）

本文件提供按英国本科常见学科分类的苏格拉底式提问模板。辅导时根据作业类型选用。

---

## 一、学术论文 (Essay) 专属

### 题目拆解阶段

- "这个题目里的关键词是什么？动词（analyse / evaluate / discuss / compare）决定了你该做什么。你查过 marking criteria 对这个动词的定义吗？"
- "这个题目在问你什么？用你自己的话回答——不准用题目里的原词。"
- "这个题目隐含了什么 assumption？有没有需要你 argument 的争议点？"
- "如果这是一道 yes/no question，你的答案是 yes 还是 no？为什么不能简单回答？"

### Thesis / Argument 构建

- "#TODO: 用一句话写出你的 thesis statement。"
- "你的 thesis 有 arguable 吗？还是它只是一个 obvious fact？"
- "有没有人可能反对你的 thesis？如果有人反对，你怎么回应？"
- "你的 conclusion 和 introduction 里的 thesis 一致吗？如果不一致，是改了 thesis 还是在 conclusion 里跑了题？"

### 论证结构

- "这一段的核心 argument 是什么？读完这段，读者能在 10 秒内说出它证明的论点吗？"
- "这个 claim 有 evidence 吗？你的 evidence 是什么类型的（数据/文献引用/逻辑推理）？"
- "你这段用了什么理论？你解释了这个理论的基本核心概念吗（不能假设 marker 知道你说的什么意思）？"
- "counterargument 在哪里？你有没有给自己为反面观点作出预先回应？"

### 引言与结论

- "你的 introduction 是不是按照 funnel 结构写的？（从宽泛背景 → 具体研究问题 → thesis → essay roadmap）"
- "你的 conclusion 有没有引入新内容？（——不应该。Conclusion 只总结和反思，不插入新东西。）"
- "引言中的 roadmap 和正文的结构匹配吗？按段落核对一下。#TODO"

## 二、数学 / 统计 专属

### 数学题

- "这道题涉及什么定理？先把定理的名字和条件说出来——不用写步骤。"
- "定理的条件你都检查过了吗？有没有哪个条件题干没满足？"
- "你能不能先猜一下答案大致是多少？范围在哪？数量级？"
- "画张图。这个函数长什么样？几何意义是什么？"
- "有没有更简单的入手方式？先代个具体数字？先简化一个特殊 case？"
- "如果是证明题：结论需要什么条件？逆推试试——从结论出发，每一步需要什么前提。"
- "#TODO: 把这一步的代数推导写出来（只写这一步，不求最终结果）。"

### 统计题

- "这是什么类型的 data？（continuous / discrete / categorical / ordinal）——这决定了你能用什么方法。"
- "用什么 test？（t-test / chi-square / ANOVA / regression）——为什么选这个？前提条件是什么？"
- "你的假设是什么？H₀ 和 H₁ 分别是什么？写出来。"
- "α level 是多少？你准备用什么来判断 significance？p-value 和 α 比较？"
- "这个结果是 statistically significant 吗？那 practically significant 吗？（效应量有多大？）"
- "你的样本量够大吗？你有没有检查 normality / homogeneity of variance 等 assumption？"
- "#TODO: 用公式写出 test statistic 的计算过程（代入你的数字，不需求出最终 p 值）。"

### 数学/统计通用

- "你有没有代回验证一下？把结果代入原式/原条件看是否成立。"
- "单位正确吗？等式两边的量纲一致吗？"
- "有没有除以 0 的危险？你有没有检查定义域？"

## 三、编程作业 专属

### 理解需求

- "输入类型是什么？输出类型是什么？先说清楚 I/O specification。"
- "你能写出 3 个测试用例吗？（正常情况 + 边界情况 + 异常情况） #TODO"
- "这个功能要求你和什么外部库/API 交互？你确认过它们的文档吗？"

### 设计阶段

- "先用注释写伪代码。不要写实际代码，一句注释 = 一个步骤。"
- "这个问题可以拆成几个函数？每个函数的单一职责是什么？"
- "你需要什么数据结构？为什么选这个？（list vs dict vs set vs tuple）"
- "时间复杂度能从 O(n²) 优化到 O(n log n) 吗？瓶颈在哪里？"

### Debug 阶段

- "错误信息读一下。Traceback 从下往上看，最后一行是什么错误？哪一行触发的？"
- "你在这个错误发生之前的变量状态是什么？加个 print 看看实际值和预期值。"
- "把你的代码讲给你宿舍的一个同学听（假装我在听），每行都解释它做什么。——如果你说不通，bug 多半在这里。"
- "这个 bug 在什么输入下触发？你能不能构造一个最小的、能稳定复现的 test case？"
- "你的 loop 跑了几次？在纸上数一遍。off-by-one 是最常见的编程错误之一。#TODO: 写出循环的准确次数。"
- "如果输入是空列表/0/None/负数，你的代码会炸吗？试一下。 #TODO"

### 代码完成后

- "有没有人能读懂你的代码？变量名有意义吗？需要写注释的地方（非平凡逻辑）写了吗？"
- "你的代码有没有重复的部分？能不能提取一个辅助函数？"
- "你能不能不跑代码，肉眼估这个算法的复杂度？"

## 四、实验 / 项目报告 专属

### 实验报告 (Lab Report)

- "你的方法部分：读者按照你的描述能复现这个实验吗？你漏了什么细节？"
- "Results 和 Discussion 分离了吗？Results = 数据呈现（表、图、描述）。Discussion = 解读（为什么会这样、和理论对比、误差分析）。"
- "实验的误差来源有哪些？random error 还是 systematic error？你量化了吗？"
- "你的图表有没有：标题、轴标签、单位、图例？"
- "你的结论和你的数据一致吗？有没有把 correlation 说成 causation？"

### 项目报告 (Project Report)

- "你的 project 的 scope 是否清晰？你做的是什么，更重要的是——不做什么？"
- "你的 methodology 的 justification 是什么？为什么选这个方法，不选另一个？"
- "你的 evaluation 是否回答了 research questions？有没有定量的 metrics 而不仅是定性的描述？"
- "limitations 和 future work 你区分了吗？Limitation = 你想做的因为时间/数据/工具限制做不了；Future work = 以后有人可以接着做什么。"

## 五、跨学科通用提问

### 学生说"I don't know where to start"

```
L0: "你觉得这道题在考什么知识点？——只看题干的线索。"
L0: "你在 lecture / seminar 里学过什么相关内容？翻一下 module handbook。"
L1: "我建议你先不要写任何东西，花 5 分钟写出 3 个你觉得和这道题相关的概念。"
```

### 学生说"I'm stuck"

```
"卡在哪一步？精确告诉我——是不知道用哪个公式/方法，还是知道公式但代入不进去，还是代入了但算不出来？"
```

### 学生说"Can you check if this is right?"

```
"我说了不能确认答案。但是你可以自己验证——把结果代回原条件试试/跑一下测试用例。"
"你觉得最可能出错的是哪一步？为什么？"
```

### 学生说"Just give me a hint"

```
L1 → L2: "好的。这道题可以分解成这几个阶段：____。你先试第一阶段。"
L2 → L3: "第一阶段的关键是 [某定理/某方法]。#TODO: 把第一步写出来。"
L3 → L3+: 不再升级。"我建议你去看 lecture notes 里关于 [前置知识] 的部分，然后来 office hours。我们先停在这里。"

## 六、软件工程专属 (Software Engineering)

### 代码调试 (Debugging)

- "你先不用改代码。用一句话描述：你期望程序做什么？（Expected Behaviour）它实际做了什么？（Actual Behaviour）"
- "Traceback 从最后一行往上看。第一个 'File ... line X' 就是你的代码中触发的错误。那一行发生了什么？"
- "你在这个错误发生前加一个 print，看看那个变量的值是不是你预期的？"
- "试试二分注释法 (Binary Comment-out Method)：注释掉一半代码，运行。Bug 还在吗？如果不在 → bug 在注释掉的那一半；如果还在 → bug 在没注释的那一半。重复。"
- "你的假设是什么？(Hypothesis) 你怎么验证它？(Test)"
- "根据教案中 Debugging Strategies，第一步是 isolate the problem（隔离问题）。你现在能精确到哪一个函数出错的吗？"

### 算法实现 (Algorithm Implementation)

- "不要写代码。先写中文伪代码，一行一步。写完了再来。 #TODO"
- "这个算法的输入规模 n 多大时就会超时？估算一下：你的时间复杂度是 O(?)，n 最大是多少？"
- "最坏情况是什么输入？手动 trace 一遍那个输入，看看代码行为。"
- "你的循环不变式 (Loop Invariant) 是什么？每次迭代前什么条件一定成立？"
- "有没有重复计算？哪里在重算同样的值？能不能缓存？"
- "根据教案中 Algorithm Analysis，先用 brute-force 写出正确版本，再考虑优化。不要一开始就想最优解。"

### 设计模式 (Design Patterns)

- "先描述上下文 (Context)：哪些部分未来会变？哪些应该稳定？"
- "你这里违反了哪个 SOLID 原则？Single Responsibility？Open-Closed？Dependency Inversion？"
- "根据教案中的 [Pattern Name]，它的 Intent（意图）是什么？你的场景匹配这个意图吗？"
- "如果明天要新增一个 [ConcreteX] 类型，你需要改动几处代码？Open-Closed 原则说应该不用改已有代码。"
- "先画类图草图，标注每个类的职责 (Responsibilities) 和协作 (Collaborations)。 #TODO"
- "这个模式的核心是：把 [What varies] 封装起来。你封装了吗？"

### 单元测试 (Unit Testing)

- "先写测试用例，不写实现。你需要覆盖哪三类情况？Normal + Edge + Error。#TODO: 每个至少 1 个。"
- "如果传入 null/空列表/负数/极大值，你的函数应该返回什么？抛出什么异常？"
- "你的测试名能看出测什么吗？格式：test_[method]_[scenario]_[expectedResult]"
- "Arrange-Act-Assert (AAA)：测试分三段——准备数据 → 执行被测函数 → 断言结果。你的 Arrange 完整吗？"
- "这个 test 测了几个 behaviour？一个 test 只应测一件事。拆开。#TODO"
- "根据教案中 Unit Testing best practice，测试之间应该独立（no shared state）。你的 test 之间有依赖吗？"

### Git 操作 (Git Operations)

- "先跑 `git status`。把输出贴在聊天里，我们一起看。"
- "你现在的 HEAD 在哪？哪个 branch？有没有 uncommitted changes？"
- "Commits 历史如何？跑 `git log --oneline -5` 看看最近的 5 次提交。"
- "合并前先 diff：`git diff target-branch...your-branch` 看看你改了什么。"
- "Commit message 写清楚你做了什么 + 为什么。#TODO: 按 Conventional Commits 格式写一条 commit message。"
- "根据教案中 Version Control 的 branching strategy（分支策略），你当前应该在哪个 branch？feature branch 还是 main？"

### 代码审查 (Code Review)

- "先说你代码的 3 个优点。认真找——命名清晰？逻辑简洁？错误处理周全？"
- "再说 3 个疑点。哪个函数最长？哪个变量名最模糊？哪个条件最复杂？"
- "这段代码的 cyclomatic complexity（圈复杂度）是多少？if/for/while 嵌套了几层？#TODO: 数一下。"
- "根据教案中的 coding standard，命名规范是什么？你的变量/函数名符合吗？"
- "有没有重复代码 (DRY violation)？哪两段看起来几乎一样？"
- "如果你是 reviewer，你最先想问的问题是？(最令人困惑的部分)"
- "这个函数超过 20 行了吗？能不能提取子函数，让每个函数只做一件事？"
- "有没有 magic number（神秘数字）？应该用什么替代？(#TODO: 定义常量)"
```

## 七、术语学习专属 (Terminology Learning)

### 理解确认

- "你如何用自己的话解释 [Term X]（[中文译名]）？不准用教科书上的原句。"
- "假设你要给一个完全不懂编程的人讲 [Term X]，你会怎么举例？"
- "这个术语在你的项目/作业中哪里出现过？或者可能用在什么地方？"
- "[Term A] 和 [Term B] 的区别是什么？如果只说一个关键区别，你会说哪个？"
- "这个术语的英文词根你知道什么意思吗？拆一下看看：poly-morph-ism = ?"

### 记忆与联系

- "这个术语和之前学的 [Related Term] 有什么联系？它们是互补还是互斥的？"
- "能不能画一张概念图 (concept map)，标出 [Term X] 和它关联的 3 个术语？"
- "给你 30 秒，用一句话 + 一个例子解释 [Term X]。现在开始。"
- "如果把 [Term X] 比作日常生活中一个东西，你会比作什么？为什么？"
- "有没有一个代码片段能展示 [Term X] 的典型形态？写出 3 行伪代码。#TODO"

### 考试准备

- "考试中如果问到 [Term X] 的定义（通常 2 marks），你打算写哪两个关键词？"
- "如果简答题问 'Explain [Term X] with an example (4 marks)'，你如何分配每个 mark 的内容？#TODO: 写出答题框架"
- "填空/选择题中，[Term X] 常和哪个术语混淆？它们的区分点是什么？"
- "如果让你出一道关于 [Term X] 的考题，你会出填空题还是简答题？题干是什么？#TODO"
- "根据教案 Chapter X 中 [Term X] 的定义（'[英文原文]'），与教科书的通用定义有何异同？考试时以哪个为准？"

### 小测反馈

- "你的定义基本正确。但是否遗漏了一个关键条件？再想想 [Term X] 的前置条件。"
- "你举的例子不太对。这个例子更像是 [Other Term] 的场景。两者的区别是？"
- "你答对了！现在试一下更难的问题：[场景题]。#TODO"
- "你的答案中这个英文关键词拼写有误。考试中拼写错误可能会扣分。更正一下。"
- "从这个错误来看，你对 [Term X] 的理解偏向了 [某方向]。建议回顾教案 [章节] 中关于 [某概念] 的定义，然后再做一次。"
- "3 题答对 1 题。薄弱点在 [某类型术语]。[中文解释这类术语的共同特征]。建议重点复习 [术语列表]。"

## 八、答题模板提炼与思维导图专属

### 模板提炼相关 (Template Extraction)

**分析原文时**：
- "这段文字的核心论证逻辑是什么？先分成几个大块，每个块一句话概括。"
- "哪些句子是通用结构（任何类似题都可以用），哪些是本题特有的具体数据？区分出来。"
- "这个解题步骤的顺序能调换吗？哪些步骤有严格的先后依赖？"
- "如果让 ChatGPT 来做这道题，它会在哪个环节卡住？——那往往就是模板中最关键的分析点。"

**使用模板时**：
- "你用了模板的哪几个步骤？有没有跳过的？为什么？"
- "这道题和模板中的示例有什么不同？模板需要怎么调整？"
- "你会给这个模板增加什么提示？学了这道题之后，模板哪里可以改进？"
- "考试时如果是变形题，你如何从模板中快速定位适用的部分？"
- "这个模板的空白框架你全填完了吗？每个 #TODO 都检查过？"

**模板对比与归纳**：
- "这道题的模板和你之前学过的 [某题型模板] 有什么异同？能不能合并成更通用的一个？"
- "你能把最近 3 道同类题的模板放在一起看一眼吗？哪些步骤是共有的？"

### 思维导图相关 (Mind Map)

**生成导图前**：
- "如果把这个知识点画成一张树状图，根节点是什么？一级分支有几个？先说出来再画。"
- "你觉得 [Topic] 和哪些你已经学过的概念有交叉关系？这些交叉关系在导图中怎么表示？"
- "按照教案的章节结构，[Chapter N] 是怎样组织知识的？先用大纲列出来。"
- "这张导图的受众是谁？你自己复习用？还是给同学讲用？这会决定细节程度。"

**使用导图时**：
- "看着这张导图，你能不看笔记口述一遍 [Topic] 的知识框架吗？录音试试。"
- "导图中 `#TODO` 的节点有哪几个？你先不看答案，尽力填补。填完后再对照。"
- "从左到右/从上到下走一遍导图，每一步用英文术语 + 中文解释口头复述。"
- "有哪些节点是这张图没有但你觉得应该加的？为什么？"

**导图反馈与优化**：
- "这张导图的层级深吗？最深几层？有没有某些分支太浅（只有一层）需要展开？"
- "有没有信息量过多的节点？一个节点的文字超过 3 行就过了——能不能拆成 2 个节点？"
- "颜色和线型帮助你区分概念类型了吗？method 是绿色、example 是橙色、todo 是黄色——这些区分对你的记忆有效吗？"
- "同课程的多张导图能不能拼成一张大图？交叉连接在哪里？"

### 两种工具的联动

- "看一下刚生成的导图。哪些分支的节点可以提炼成一个答题模板？"
- "这个模板中的每个步骤，在导图中能找到对应的节点吗？找不到的说明模板或导图有遗漏。"
- "用 @mindmap 画出这个模板的结构，然后用 @extract-template 提炼图中文法的模式化规律。"
- "考试复习时：先用 @mindmap 构建全局框架，再用 @extract-template 总结每个题型的答题套路，最后用 @learn 攻破核心术语。"
