# 苏格拉底式提问模板（按学科）

本文件提供按英国本科常见学科分类的苏格拉底式提问模板。辅导时根据作业类型选用。

---

## 一、学术论文 (Essay) 专属

### 题目拆解阶段

- "这个题目里的关键词是什么？动词（analyse / evaluate / discuss / compare）决定了你该做什么。你查过 marking criteria 对这个动词的定义吗？"
- "这个题目在问你什么？用你自己的话回答——不准用题目里的原词。"
- "这个题目隐含了什么 assumption？有没有需要你 argument 的争议点？"
- "如果这是一道 yes/no question，你的答案是 yes 还是 no？为什么不能简单回答？"

### Thesis / Argument 构建

- "#TODO: 用一句话写出你的 thesis statement。"
- "你的 thesis 有 arguable 吗？还是它只是一个 obvious fact？"
- "有没有人可能反对你的 thesis？如果有人反对，你怎么回应？"
- "你的 conclusion 和 introduction 里的 thesis 一致吗？如果不一致，是改了 thesis 还是在 conclusion 里跑了题？"

### 论证结构

- "这一段的核心 argument 是什么？读完这段，读者能在 10 秒内说出它证明的论点吗？"
- "这个 claim 有 evidence 吗？你的 evidence 是什么类型的（数据/文献引用/逻辑推理）？"
- "你这段用了什么理论？你解释了这个理论的基本核心概念吗（不能假设 marker 知道你说的什么意思）？"
- "counterargument 在哪里？你有没有给自己为反面观点作出预先回应？"

### 引言与结论

- "你的 introduction 是不是按照 funnel 结构写的？（从宽泛背景 → 具体研究问题 → thesis → essay roadmap）"
- "你的 conclusion 有没有引入新内容？（——不应该。Conclusion 只总结和反思，不插入新东西。）"
- "引言中的 roadmap 和正文的结构匹配吗？按段落核对一下。#TODO"

## 二、数学 / 统计 专属

### 数学题

- "这道题涉及什么定理？先把定理的名字和条件说出来——不用写步骤。"
- "定理的条件你都检查过了吗？有没有哪个条件题干没满足？"
- "你能不能先猜一下答案大致是多少？范围在哪？数量级？"
- "画张图。这个函数长什么样？几何意义是什么？"
- "有没有更简单的入手方式？先代个具体数字？先简化一个特殊 case？"
- "如果是证明题：结论需要什么条件？逆推试试——从结论出发，每一步需要什么前提。"
- "#TODO: 把这一步的代数推导写出来（只写这一步，不求最终结果）。"

### 统计题

- "这是什么类型的 data？（continuous / discrete / categorical / ordinal）——这决定了你能用什么方法。"
- "用什么 test？（t-test / chi-square / ANOVA / regression）——为什么选这个？前提条件是什么？"
- "你的假设是什么？H₀ 和 H₁ 分别是什么？写出来。"
- "α level 是多少？你准备用什么来判断 significance？p-value 和 α 比较？"
- "这个结果是 statistically significant 吗？那 practically significant 吗？（效应量有多大？）"
- "你的样本量够大吗？你有没有检查 normality / homogeneity of variance 等 assumption？"
- "#TODO: 用公式写出 test statistic 的计算过程（代入你的数字，不需求出最终 p 值）。"

### 数学/统计通用

- "你有没有代回验证一下？把结果代入原式/原条件看是否成立。"
- "单位正确吗？等式两边的量纲一致吗？"
- "有没有除以 0 的危险？你有没有检查定义域？"

## 三、编程作业 专属

### 理解需求

- "输入类型是什么？输出类型是什么？先说清楚 I/O specification。"
- "你能写出 3 个测试用例吗？（正常情况 + 边界情况 + 异常情况） #TODO"
- "这个功能要求你和什么外部库/API 交互？你确认过它们的文档吗？"

### 设计阶段

- "先用注释写伪代码。不要写实际代码，一句注释 = 一个步骤。"
- "这个问题可以拆成几个函数？每个函数的单一职责是什么？"
- "你需要什么数据结构？为什么选这个？（list vs dict vs set vs tuple）"
- "时间复杂度能从 O(n²) 优化到 O(n log n) 吗？瓶颈在哪里？"

### Debug 阶段

- "错误信息读一下。Traceback 从下往上看，最后一行是什么错误？哪一行触发的？"
- "你在这个错误发生之前的变量状态是什么？加个 print 看看实际值和预期值。"
- "把你的代码讲给你宿舍的一个同学听（假装我在听），每行都解释它做什么。——如果你说不通，bug 多半在这里。"
- "这个 bug 在什么输入下触发？你能不能构造一个最小的、能稳定复现的 test case？"
- "你的 loop 跑了几次？在纸上数一遍。off-by-one 是最常见的编程错误之一。#TODO: 写出循环的准确次数。"
- "如果输入是空列表/0/None/负数，你的代码会炸吗？试一下。 #TODO"

### 代码完成后

- "有没有人能读懂你的代码？变量名有意义吗？需要写注释的地方（非平凡逻辑）写了吗？"
- "你的代码有没有重复的部分？能不能提取一个辅助函数？"
- "你能不能不跑代码，肉眼估这个算法的复杂度？"

## 四、实验 / 项目报告 专属

### 实验报告 (Lab Report)

- "你的方法部分：读者按照你的描述能复现这个实验吗？你漏了什么细节？"
- "Results 和 Discussion 分离了吗？Results = 数据呈现（表、图、描述）。Discussion = 解读（为什么会这样、和理论对比、误差分析）。"
- "实验的误差来源有哪些？random error 还是 systematic error？你量化了吗？"
- "你的图表有没有：标题、轴标签、单位、图例？"
- "你的结论和你的数据一致吗？有没有把 correlation 说成 causation？"

### 项目报告 (Project Report)

- "你的 project 的 scope 是否清晰？你做的是什么，更重要的是——不做什么？"
- "你的 methodology 的 justification 是什么？为什么选这个方法，不选另一个？"
- "你的 evaluation 是否回答了 research questions？有没有定量的 metrics 而不仅是定性的描述？"
- "limitations 和 future work 你区分了吗？Limitation = 你想做的因为时间/数据/工具限制做不了；Future work = 以后有人可以接着做什么。"

## 五、跨学科通用提问

### 学生说"I don't know where to start"

```
L0: "你觉得这道题在考什么知识点？——只看题干的线索。"
L0: "你在 lecture / seminar 里学过什么相关内容？翻一下 module handbook。"
L1: "我建议你先不要写任何东西，花 5 分钟写出 3 个你觉得和这道题相关的概念。"
```

### 学生说"I'm stuck"

```
"卡在哪一步？精确告诉我——是不知道用哪个公式/方法，还是知道公式但代入不进去，还是代入了但算不出来？"
```

### 学生说"Can you check if this is right?"

```
"我说了不能确认答案。但是你可以自己验证——把结果代回原条件试试/跑一下测试用例。"
"你觉得最可能出错的是哪一步？为什么？"
```

### 学生说"Just give me a hint"

```
L1 → L2: "好的。这道题可以分解成这几个阶段：____。你先试第一阶段。"
L2 → L3: "第一阶段的关键是 [某定理/某方法]。#TODO: 把第一步写出来。"
L3 → L3+: 不再升级。"我建议你去看 lecture notes 里关于 [前置知识] 的部分，然后来 office hours。我们先停在这里。"
```
